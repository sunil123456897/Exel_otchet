# 🏗 Архитектура Master-Report v5.5 "Elite"

Проект следует принципам слоистой архитектуры (Layered Architecture) с четким разделением ответственности.

## 1. Domain Layer (`APP/core/domain/`)
"Сердце" системы, содержащее только бизнес-логику и правила.
- **`logic_service.py`**: Реализация финансовых правил расчета прибыли, комиссий и маршрутизации транзакций.
- **`data_schemas.py`**: Строгие модели данных на базе **Pydantic**. Гарантируют, что некорректные данные не попадут в систему.
- **`interfaces.py`**: Определения контрактов для компонентов инфраструктуры (Dependency Inversion).

## 2. Infrastructure Layer (`APP/core/infra/`)
Реализация технических деталей и интеграция с внешними системами.
- **Ingestion**: Парсинг Excel-файлов через `CalamineReader`.
- **Persistence**: Хранение кэша и метаданных в **SQLite** с поддержкой режима WAL.
- **Discovery**: Поиск файлов в сети и локальная оптимизация путей.
- **Export**: Формирование итоговых отчетов с применением стилей и правил форматирования.

## 3. UI Layer (`APP/core/ui/`)
Слой взаимодействия с пользователем.
- Использует **Tkinter** с кастомной темой (`theme.py`).
- Взаимодействует с ядром через `AppController`, что позволяет в будущем легко заменить UI (например, на PySide6).

## 4. Контроллер приложения (`APP/core/app_controller.py`)
Оркестратор, координирующий работу слоев. Не содержит бизнес-логики, а лишь вызывает методы сервисов в нужном порядке.
