# Operations Guide

Практическая инструкция по запуску и обслуживанию приложения на рабочих Windows-ПК.

## Как Запускать

Основной способ:

```bat
ЗАПУСК.bat
```

Обновление с GitHub и запуск:

```bat
ОБНОВИТЬ_И_ЗАПУСТИТЬ.bat
```

Альтернативно:

```bash
python APP/main.py
```

Рабочая папка приложения обычно выглядит так:

```text
APP/
Master_Report.xlsx
REPORTS/
РСЧ/
ЗАПУСК.bat
```

## Требования К Рабочему ПК

- Windows.
- Python 3.12+.
- Доступ к папкам отчетов.
- Доступ на запись к папке приложения, потому что там создаются `cache.db`, логи и выходные файлы.
- Если отчеты на сетевом диске, диск должен быть подключен до запуска программы.

## Python Окружение

`ЗАПУСК.bat` сначала ищет локальное окружение `.venv` рядом с файлом запуска. Если его нет и доступен Python launcher `py -3.12`, запускатор создаст `.venv` автоматически и поставит зависимости туда. Это защищает программу от конфликтов с глобальными пакетами Windows-пользователя.

Ручная подготовка окружения:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Если `.venv` создать нельзя, запускатор может использовать обычный `python` из `PATH` и ставить недостающие зависимости в user site-packages. Такой режим менее надежен и может отличаться на разных ПК.

Решение для переноса: `.venv` остается основным и рекомендуемым режимом. Fallback в user site-packages оставлен только как аварийная совместимость для рабочих ПК, где создание `.venv` заблокировано правами или политиками Windows. Если в `startup_log.txt` есть строка `WARNING: local .venv is unavailable`, такой ПК нужно считать запущенным в degraded-режиме и по возможности настроить локальное `.venv`.

Проверку зависимостей делайте именно через `.venv`:

```powershell
.\.venv\Scripts\python.exe -m pip check
```

Команда `python -m pip check` без `.venv` проверяет общий Python пользователя и может показывать чужие конфликты, которые не относятся к этой программе.

## Обновление На Рабочем ПК

Для удаленного обновления без ручной настройки используйте:

```bat
ОБНОВИТЬ_И_ЗАПУСТИТЬ.bat
```

Скрипт делает безопасный минимум:

- проверяет репозиторий `sunil123456897/Exel_otchet`;
- сохраняет локальные `APP/config.yaml` и `APP/employees.yaml` в `.update_backups/`;
- обновляет файлы программы из ветки `main`;
- возвращает локальные настройки после обновления;
- обновляет зависимости в `.venv`, если окружение уже создано;
- запускает обычный `ЗАПУСК.bat`.

Если на ПК установлен Git и папка является клоном репозитория, используется `git pull --ff-only`. Если Git недоступен или папка была просто скопирована, используется zip-скачивание через PowerShell. В обоих режимах рабочие Excel-файлы и локальные настройки не должны удаляться.

Лог обновления:

```text
update_log.txt
```

## Smoke Checklist Для Нового ПК

1. Скопировать или скачать весь проект целиком, не только `APP/`.
2. Запустить `ЗАПУСК.bat`.
3. Проверить `startup_log.txt`: нет `WARNING: local .venv is unavailable`, если политики Windows не запрещают `.venv`.
4. Проверить, что `.venv/` создан рядом с `ЗАПУСК.bat`.
5. Проверить `APP/config.yaml`: нет путей вида `E:\Dlia Dashi\Version5\...` от чужого ПК.
6. Проверить `APP/employees.yaml`: пути сотрудников открываются или корректно указывают на `REPORTS/`/сетевые папки.
7. Запустить обычный refresh/status. Он не должен делать полный сетевой scan при штатных привязках.
8. Собрать общий мастер за одну дату.
9. Собрать отчеты Бориса и Ивана.
10. Собрать РСЧ за дату с известными строками.
11. Проверить негативный сценарий РСЧ: дата без строк должна дать ошибку, а не успешный файл `0 строк`.
12. Запустить автосверку и проверить один файл с листами `Общий`, `Борис`, `Иван`.
13. Открыть Excel-выходы: нет `#REF!`, `#DIV/0!`, `#VALUE!`, `#NAME?`; цвета warning/critical видны.
14. Проверить, что перед повторной сборкой существующего `.xlsx` появился backup в `backups/excel_outputs/`.
15. Запустить `python tools/timing_report.py --date ДД.ММ.ГГГГ` и сохранить результат из `benchmarks/` для сравнения с другими ПК.

## Smoke Checklist Для Q/Z

1. В Проводнике открыть `Q:\Отчет кураторов 1`, `Q:\Отчет кураторов 2`, `Q:\Отчет кураторов 3` или аналогичные папки на `Z:`.
2. Проверить права чтения на файлы сотрудников и права записи в папку приложения.
3. Проверить, что в `APP/config.yaml` указаны правильные `network.drive_letters`.
4. Запустить refresh/status. Если он резко дольше обычного, проверить доступность сетевых папок и `discovery_cache`.
5. Запустить `python tools/timing_report.py --location QZ --date ДД.ММ.ГГГГ` на ПК с подключенным сетевым диском.
6. Если Q/Z недоступен, программа должна показать понятную проблему с путями, а не зависать на полном scan.

## Безопасная Уборка Папки

Можно удалять локальные кэши разработки, если программа закрыта:

- `.mypy_cache/`
- `.pytest_cache/`
- `.ruff_cache/`
- `**/__pycache__/`
- `benchmarks/` старше нужной истории замеров

Не удаляйте Excel-источники и рабочие папки `REPORTS/`, `РСЧ/`, `рсч всех/`, если заранее не сделали копию и не проверили, что эти файлы не нужны для сверки.

## Backup И Восстановление Excel

Перед перезаписью существующего Excel-выхода программа создает копию. Для master/curator отчетов используется `paths.archive_dir`, по умолчанию:

```text
backups/excel_outputs/<имя-отчета>/
```

Для РСЧ и сверки, где нет отдельного config-контекста, backup создается рядом с выходным файлом:

```text
<папка-выходного-файла>/backups/excel_outputs/<имя-отчета>/
```

Количество копий на один файл регулируется:

```yaml
backup:
  excel_keep: 10
```

Для восстановления:

1. Закрыть Excel.
2. Найти последний корректный timestamped `.xlsx` в backup-папке.
3. Скопировать его поверх поврежденного выходного файла.
4. Повторить только нужную сборку.

Если backup не может быть создан перед перезаписью, сохранение отчета прерывается. Это лучше, чем потерять последний рабочий файл.

## Benchmark И Контроль Регрессий

Команда:

```powershell
python tools/timing_report.py --date 12.05.2026 --period-start 01.05.2026 --period-end 22.05.2026
```

Результаты сохраняются в:

```text
benchmarks/timing_<timestamp>.md
benchmarks/timing_<timestamp>.json
```

Скрипт сравнивает новый замер с предыдущим JSON в `benchmarks/` и показывает регрессии, если `total_s` этапа вырос на 20% или больше. Порог можно изменить:

```powershell
python tools/timing_report.py --regression-threshold 0.30
```

`sqlite_s` в отчете является суммой времени обернутых SQLite-вызовов по потокам и может быть больше `total_s`; для пользовательской скорости главным считается `total_s`.

## Настройка Путей

Главный файл настроек:

```text
APP/config.yaml
```

Для рабочего ПК с сетевым диском `Q:` типовая настройка:

```yaml
paths:
  master_file: ../Master_Report.xlsx
  source_roots:
    - Q:\Отчет кураторов 1
    - Q:\Отчет кураторов 2
    - Q:\Отчет кураторов 3
database:
  path: cache.db
  schema_path: db_schema.sql
rsch:
  last_output_dir: ../РСЧ
  mode: combined
performance:
  isolate_calamine: true
  max_workers:
backup:
  excel_keep: 10
```

Не используйте абсолютные пути вида `E:\Dlia Dashi\Version5\APP\cache.db` на чужом рабочем ПК. Такой путь привязывает программу к конкретному компьютеру.

## Правила Надежности РСЧ И Сверки

Ручная сборка РСЧ с 0 строками за выбранную дату или выбранный период считается ошибкой, а не успешным пустым отчетом. Для пакетной сборки периода пустые даты пропускаются, но если за весь период не найдено ни одной строки, пользователь получает ошибку. Это защищает от ситуации, когда недоступный источник, неверная дата или неверный фильтр маскируются под успешный файл.

Если часть листов РСЧ не читается, но валидные листы дали строки, сборка продолжается, а сообщение пользователю содержит краткий список проблемных листов. Если все выбранные листы/файлы оказались проблемными и строк нет, сборка завершается ошибкой.

В сверку расхождений не попадают строки кураторского отчета с фильтрами `доп сф`, `касса`, `зачет`, `посредник`, `корректировка`. Этот список закреплен по текущему ТЗ заказчика; при изменении бизнес-правила нужно обновлять и код, и регрессионные тесты.

## Логи

Основные файлы:

```text
startup_log.txt
APP/startup_log.txt

```

При ошибке запуска сначала смотрите `startup_log.txt`.

## Типовые Ошибки

### Configured DB path is not writable

Пример:

```text
Configured DB path is not writable: E:\...\APP\cache.db
```

Причина: в `APP/config.yaml` остался путь от другого компьютера.

Исправление:

```yaml
database:
  path: cache.db
  schema_path: db_schema.sql
```

### Не Видит Сетевые Отчеты

Проверьте:

- диск `Q:` подключен;
- папки `Q:\Отчет кураторов 1`, `Q:\Отчет кураторов 2`, `Q:\Отчет кураторов 3` открываются в проводнике;
- у пользователя есть права на чтение;
- в `APP/config.yaml` нет старого пути на `E:` или другой компьютер.

### Окно Не Помещается На Экран

Интерфейс подстраивается под экран и имеет прокрутку в боковой панели. Если окно все равно выглядит слишком крупным:

- проверьте масштаб Windows;
- попробуйте 100% или 125%;
- разверните окно вручную;
- убедитесь, что панель задач не занимает слишком много места.

### Запуск Долго Сканирует Сеть

Стартовый статус не должен делать полный сетевой перескан. Если в логе снова видно долгий проход по сетевым корням при обычном запуске, проверяйте связку:

```text
APP/core/app_controller.py
APP/core/infra/discovery_service.py
```

Полный сетевой поиск допустим, когда нужно найти переименованные или перенесенные файлы.

### Ошибка `_overlapped` / `WinError 10106` В Codex

Если падают `pytest`, `mypy` или импорт `asyncio` внутри Codex Desktop, а обычный Python/OpenCode работает, это проблема окружения Codex. Для проекта это не считается бизнес-регрессией.

## Безопасная Проверка После Переноса На Новый ПК

1. Открыть `APP/config.yaml`.
2. Убедиться, что `database.path` относительный: `cache.db`.
3. Проверить, что сетевые папки открываются в проводнике.
4. Запустить `ЗАПУСК.bat`.
5. Выбрать дату и нажать обновление статуса.
6. Собрать один дневной отчет.
7. Открыть итоговый Excel и проверить лист выбранной даты.

## Что Не Удалять При Уборке

Не удалять:

- `*.xlsx`, `*.xlsm`, `*.xlsb`, `*.xls`;
- `APP/config.yaml`;
- `APP/employees.yaml`;
- `Master_Report.xlsx`;
- папки `REPORTS`, `РСЧ`, `рсч всех`, если там реальные данные;
- `cache.db`, если нужен текущий кэш.

Обычно можно удалить временные папки `tmp_pytest_*`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`, если не нужны результаты прошлых проверок.
