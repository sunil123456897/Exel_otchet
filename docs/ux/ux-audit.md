# UX Audit — Phase 2.2

## Метаданные
- Дата: 2026-06-26
- Проект: Master-Report v5.5
- Источник: docs/specs/user-stories.md + docs/specs/edge-cases.md + ручной анализ UI-кода
- Аудитор: AI QA cycle
- Объём: 23 UX-нарушения (5 major, 12 minor, 6 cosmetic)

---

## Методология

UX-аудит проведён по следующим критериям:
1. **Feedback**: видит ли пользователь результат своих действий?
2. **Error prevention**: защищает ли UI от ошибок до их совершения?
3. **Recovery**: может ли пользователь восстановиться после ошибки?
4. **Consistency**: единообразны ли паттерны взаимодействия?
5. **Accessibility**: keyboard nav, contrast, focus management
6. **Performance perception**: progress, ETA, cancel
7. **Information hierarchy**: что важно, что второстепенно

Анализ выполнен на основе кода UI-слоя (`APP/core/ui/`) и user-stories.

## UX-001 — MAJOR: Нет подтверждения перед удалением сотрудника
- **Фича**: F-005
- **Файл**: `APP/core/ui/sidebar/employees_panel.py`
- **Проблема**: Удаление сотрудника происходит без подтверждения. Если пользователь случайно нажмёт «Удалить», сотрудник исчезнет из employees.yaml без возможности отмены.
- **User story**: US-005-S3
- **Рекомендация**: Добавить `messagebox.askyesno("Удалить сотрудника?", "Удалить «{name}»? Действие необратимо.")` перед удалением.
- **Приоритет**: P1

## UX-002 — MAJOR: Нет подтверждения перед очисткой списка сотрудников
- **Фича**: F-005
- **Файл**: `APP/core/ui/sidebar/employees_panel.py`
- **Проблема**: Если есть кнопка «Очистить список», она удаляет всех сотрудников без подтверждения.
- **Рекомендация**: `messagebox.askyesno` с предупреждением.
- **Приоритет**: P1

## UX-003 — MAJOR: Toast error не показывает детали ошибки
- **Фича**: F-026
- **Файл**: `APP/core/ui/widgets/toast.py`
- **Проблема**: При ошибке консолидации toast показывает краткое сообщение («Ошибка сборки»), но не показывает причину. Пользователь не понимает, что делать.
- **Рекомендация**: Добавить expandable detail section в toast или кнопку «Подробнее» для error toast.
- **Приоритет**: P2

## UX-004 — MAJOR: Нет валидации периода в реальном времени
- **Фича**: F-006, F-010
- **Файл**: `APP/core/ui/sidebar/date_panel.py`
- **Проблема**: Пользователь может выбрать start_date > end_date и нажать «СОБРАТЬ ЗА ПЕРИОД» — только тогда получит messagebox.showerror. Валидация происходит слишком поздно.
- **Рекомендация**: При выборе start > end автоматически swap или disable кнопку «СОБРАТЬ ЗА ПЕРИОД» с tooltip «Невалидный период».
- **Приоритет**: P2

## UX-005 — MAJOR: Cancel не показывает, что было отменено
- **Фича**: F-021
- **Файл**: `APP/core/ui/main_window.py`
- **Проблема**: При отмене консолидации toast показывает «Операция отменена», но не показывает, сколько файлов было обработано до отмены. Пользователь не знает, есть ли .partial.xlsx.
- **Рекомендация**: Toast: «Отменено на 45%. Обработано 3 из 5 файлов. Частичный отчёт: report.partial.xlsx».
- **Приоритет**: P2

## UX-006 — MINOR: Нет keyboard shortcut для основных операций
- **Фича**: F-008, F-013, F-015
- **Проблема**: Нет hotkeys для «Собрать день» (Ctrl+D), «Собрать РСЧ» (Ctrl+R), «Сверить» (Ctrl+V). Пользователь вынужден использовать мышь.
- **Рекомендация**: Добавить accelerators в menu/buttons.
- **Приоритет**: P3

## UX-007 — MINOR: Progress bar не показывает текущий файл
- **Фича**: F-024
- **Проблема**: Progress bar показывает процент, но не показывает, какой файл обрабатывается сейчас. При 5 сотрудниках это не критично, при 50 — непонятно, что зависло.
- **Рекомендация**: Status bar: «Обработка: ivan_petrov.xlsx (3 из 5)».
- **Приоритет**: P3

## UX-008 — MINOR: Нет истории операций
- **Фича**: F-023
- **Проблема**: Сессии сохраняются в SQLite, но UI не показывает историю операций. Пользователь не может посмотреть, что было сделано вчера.
- **Рекомендация**: Вкладка «История» с таблицей сессий (дата, тип, статус, кол-во строк).
- **Приоритет**: P3

## UX-009 — MINOR: Settings dialog не показывает diff
- **Фича**: F-022
- **Проблема**: При изменении настроек пользователь не видит, что именно изменилось (старое → новое значение).
- **Рекомендация**: Подсветка изменённых полей или diff-режим.
- **Приоритет**: P4

## UX-010 — MINOR: Нет drag-and-drop для файлов
- **Фича**: F-005, F-020
- **Проблема**: Привязка файлов к сотруднику требует диалога выбора файла. Нет drag-and-drop из проводника.
- **Рекомендация**: TkinterDnD2 или tkinterdnd2 для drag-and-drop.
- **Приоритет**: P4

## UX-011 — MINOR: Tooltip задержка слишком длинная
- **Фича**: F-037
- **Файл**: `APP/core/ui/widgets/tooltip.py`
- **Проблема**: Tooltip появляется через ~500мс, что ощущается медленным для опытных пользователей.
- **Рекомендация**: Уменьшить до 300мс или сделать настраиваемым.
- **Приоритет**: P4

## UX-012 — MINOR: Нет сортировки в таблице сотрудников
- **Фича**: F-034
- **Проблема**: Таблица сотрудников не sortable по колонкам (имя, статус, файл).
- **Рекомендация**: Clickable headers для сортировки.
- **Приоритет**: P4

## UX-013 — MINOR: Нет фильтра по статусу
- **Фича**: F-034
- **Проблема**: Нельзя отфильтровать сотрудников по статусу («только ГОТОВО», «только должники»).
- **Рекомендация**: Dropdown фильтра статусов.
- **Приоритет**: P4

## UX-014 — MINOR: Date picker не показывает день недели
- **Фича**: F-006
- **Проблема**: При выборе даты не видно день недели (понедельник/вторник), что важно для финансовых отчётов.
- **Рекомендация**: Показывать день недели рядом с датой.
- **Приоритет**: P4

## UX-015 — MINOR: Нет batch-операций с сотрудниками
- **Фича**: F-005
- **Проблема**: Нельзя выбрать нескольких сотрудников и удалить/привязать файл сразу.
- **Рекомендация**: Multi-select в таблице + batch actions.
- **Приоритет**: P4

## UX-016 — MINOR: Settings — нет reset to defaults
- **Фича**: F-022
- **Проблема**: Нет кнопки «Сбросить к значениям по умолчанию».
- **Рекомендация**: Button «Reset to defaults» с подтверждением.
- **Приоритет**: P4

## UX-017 — MINOR: Нет индикатора сетевого диска
- **Фича**: F-029
- **Проблема**: Пользователь не видит, доступен ли сетевой диск Q:, пока не нажмёт «Обновить статус».
- **Рекомендация**: Status indicator (зелёный/красный) рядом с путём.
- **Приоритет**: P4

## UX-018 — COSMETIC: Иконки кнопок не всегда понятны
- **Фича**: F-008, F-013, F-015
- **Проблема**: Иконки ⚡, 🧾, ✅ не интуитивны без текста. Текст рядом есть, но иконки дублируют.

## UX-020 — COSMETIC: Toast colors не соответствуют severity
- **Фича**: F-026
- **Проблема**: Warning toast использует жёлтый, но в dark theme контраст недостаточен.
- **Рекомендация**: Проверить WCAG AA контраст для всех тем.

## UX-021 — COSMETIC: Нет empty state для таблицы сотрудников
- **Фича**: F-005
- **Проблема**: При пустом списке сотрудников таблица пустая без подсказки.

- **Приоритет**: P5

## UX-022 — COSMETIC: Нет empty state для дашборда
- **Фича**: F-025
- **Проблема**: При отсутствии данных дашборд пустой.
- **Рекомендация**: «Нет данных. Нажмите «Собрать день» для формирования отчёта».

## UX-023 — COSMETIC: Settings dialog — вкладки без иконок
- **Фича**: F-022
- **Проблема**: Вкладки в Settings только текстовые, без иконок для быстрой навигации.
- **Рекомендация**: Добавить иконки к вкладкам.
- **Приоритет**: P5

## Заключение

Приложение имеет функционально полный UI, но страдает от типичных проблем desktop Tkinter-приложений:
1. **Недостаточная защита от случайных действий** (UX-001, UX-002) — критично
2. **Слабая обратная связь при ошибках** (UX-003, UX-005) — значимо
3. **Отсутствие современных паттернов** (drag-drop, history, sorting) — minor

Рекомендуется исправить P1+P2 (5 нарушений) в Phase 3, остальные отложить на следующую итерацию.
