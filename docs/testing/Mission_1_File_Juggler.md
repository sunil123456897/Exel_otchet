# Миссия 1: Жонглер файлами (File Juggler) 🤹‍♂️

**Цель**: Проверка устойчивости приложения к внешним изменениям файловой системы и блокировкам файлов во время выполнения операций.

---

## 🛠 Подготовка
1. Убедитесь, что в `config.yaml` прописаны пути к нескольким тестовым отчетам сотрудников.
2. Подготовьте файл `Master_Report.xlsx` (или убедитесь, что он будет создан в корне/целевой папке).
3. Запустите приложение.

---

## 📝 Чек-лист

### 1. Блокировка целевого файла (Excel Lock)
- [ ] Откройте финальный файл консолидации (`Master_Report.xlsx`) в Microsoft Excel.
- [ ] Кликните по любой ячейке и войдите в **режим редактирования** (курсор должен мигать внутри ячейки).
- [ ] В приложении нажмите кнопку `⚡ СОБРАТЬ ДЕНЬ`.
- [ ] **Ожидаемый результат**: Приложение должно вывести информативное сообщение об ошибке (например, "Файл занят другим процессом") вместо "тихого" вылета или зависания.

### 2. Исчезновение исходных данных "на лету"
- [ ] Нажмите `🔄 Обновить статус`. Дождитесь появления списка сотрудников.
- [ ] Нажмите `⚡ СОБРАТЬ ДЕНЬ`.
- [ ] Пока идет полоса прогресса (Progress Bar), быстро переименуйте папку одного из сотрудников или сам файл отчета в Проводнике.
- [ ] **Ожидаемый результат**: Лог должен зафиксировать ошибку доступа к конкретному файлу, но общая консолидация должна завершиться для остальных файлов.

### 3. Саботаж конфигурации во время записи
- [ ] Запустите `🌍 СОБРАТЬ ВСЕ ДАТЫ`.
- [ ] Во время активной работы (когда в логах бегут строки) удалите файл `config.yaml` из папки приложения.
- [ ] **Ожидаемый результат**: Приложение не должно упасть с критической ошибкой (Segment Fault). Оно может выдать ошибку при попытке сохранить обновленные пути в конце, но должно корректно обработать исключение.

### 4. Атака на базу данных (SQLite)
- [ ] Найдите файл `cache.db` (и `cache.db-wal`, если есть) в корневой папке.
- [ ] Во время выполнения `🔄 Обновить статус` попробуйте удалить или переместить файл `cache.db`.
- [ ] **Ожидаемый результат**: Приложение должно выдать ошибку "Database disk image is malformed" или "Unable to open database file", но остаться запущенным.

### 5. Сетевой разрыв (имитация)
- [ ] *Если отчеты лежат на сетевом диске или флешке*: Запустите консолидацию.
- [ ] Физически извлеките флешку или отключите сетевой интерфейс в середине процесса.
- [ ] **Ожидаемый результат**: Корректная обработка Timeout или "Path not found" в логах. Отсутствие бесконечного ожидания (зависания интерфейса).

---

## 🚩 Правило HARD STOP
**Тест считается ПРОВАЛЕННЫМ, если:**
1. Произошел "Silent Crash" (окно просто закрылось без сообщения об ошибке).
2. Данные в `Master_Report.xlsx` оказались повреждены (неоткрываемый файл).
3. Процесс `python.exe` завис в памяти и потребляет 100% CPU после закрытия окна.
