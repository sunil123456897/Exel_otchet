# Миссия 2: Хаотичный кликер (Chaotic Clicker) 🖱️💣

**Цель**: Стресс-тест графического интерфейса, многопоточности и механизмов предотвращения конфликтов состояний.

---

## 🛠 Подготовка
1. Запустите приложение.
2. Подготовьте "тяжелый" набор данных (много файлов сотрудников, желательно по сети), чтобы процесс консолидации длился более 5 секунд.
3. Откройте Диспетчер задач (Task Manager) Windows.

---

## 📝 Чек-лист

### 1. Кнопочный спам (Button Spamming)
- [ ] Нажмите кнопку `⚡ СОБРАТЬ ДЕНЬ` 10 раз подряд максимально быстро.
- [ ] **Ожидаемый результат**: Приложение должно заблокировать кнопку (состояние disabled) после первого клика. Повторные клики не должны порождать 10 параллельных потоков сборки. Интерфейс должен оставаться отзывчивым.

### 2. Прерывание в середине полета (Window Close)
- [ ] Запустите `🌍 СОБРАТЬ ВСЕ ДАТЫ`.
- [ ] Пока полоса прогресса (Progress Bar) находится в диапазоне 20-80%, нажмите крестик в правом верхнем углу (закрыть окно).
- [ ] **Ожидаемый результат**: Приложение должно либо корректно завершить фоновые потоки перед закрытием, либо вывести предупреждение ("Процесс идет, вы уверены?"). Процесс `python.exe` должен исчезнуть из Диспетчера задач.

### 3. Внезапная смерть (Kill Process)
- [ ] Запустите консолидацию.
- [ ] В Диспетчере задач принудительно завершите процесс приложения (Снять задачу / End Task) во время активного заполнения данных в `Master_Report.xlsx`.
- [ ] Снова запустите приложение.
- [ ] **Ожидаемый результат**: Проверка целостности при запуске. База данных `cache.db` не должна быть повреждена. Последний сеанс в логах помечен как незавершенный (если реализовано), либо просто доступна новая сборка без ошибок.

### 4. Машина времени (Calendar Tampering)
- [ ] Нажмите `🌍 СОБРАТЬ ВСЕ ДАТЫ`.
- [ ] Пока идет сборка, быстро меняйте даты в календаре (Calendar Widget) или нажимайте `🔄 Обновить статус`.
- [ ] **Ожидаемый результат**: Фоновый процесс сборки должен продолжать работу с теми параметрами, с которыми он был запущен. Смена даты в интерфейсе не должна изменять логику уже запущенного потока ("Race Condition").

### 5. Динамическое удаление сотрудников
- [ ] Во время `🔄 Обновить статус`, кликните правой кнопкой мыши по сотруднику и выберите `Удалить` (если есть такая опция) или используйте кнопку удаления.
- [ ] **Ожидаемый результат**: Приложение должно запретить удаление или изменение конфигурации сотрудников во время активного процесса сканирования/чтения.

---

## 🚩 Правило HARD STOP
**Тест считается ПРОВАЛЕННЫМ, если:**
1. Произошло наложение интерфейсов (один Progress Bar поверх другого).
2. Приложение зависло ("Не отвечает") более чем на 10 секунд.
3. Данные из одного сеанса перемешались с данными из другого (например, из-за смены даты на лету).
4. После "Убийства процесса" база данных при следующем запуске выдает ошибку "Locked" или "Busy".
