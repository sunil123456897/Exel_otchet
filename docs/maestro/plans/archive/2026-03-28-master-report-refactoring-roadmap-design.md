# Дизайн-документ: Рефакторинг Master Report

## 1. Постановка проблемы (Problem Statement)
Текущая система автоматизации финансовых отчетов «Master Report» достигла предела возможностей архитектуры на базе прямых манипуляций с Excel. Основные проблемы: низкая скорость обработки сотен файлов, частые конфликты доступа (блокировки) в локальной сети, отсутствие строгой схемы данных и высокая сложность поддержки из-за переплетения логики ввода-вывода и интерфейса.

**Цель**: Создать отказоустойчивый конвейер обработки данных с использованием SQLite в качестве вычислительного ядра, сохраняя Excel как входной и выходной интерфейс.

## 2. Требования (Requirements)
### Функциональные:
- **[REQ-1.1]** Консолидация данных из Excel в SQLite кэш (Decision: SQLite3).
- **[REQ-1.2]** Умное отслеживание изменений (Decision: FileSystem Inodes/MD5).
- **[REQ-1.3]** Версионность сессий обработки (Decision: SQL Session Tables).
- **[REQ-1.4]** Глубокая валидация отчетов кураторов (Decision: Validation Layer).
- **[REQ-1.5]** Генерация мастер-отчета Excel с форматированием (Decision: openpyxl styling).

### Нефункциональные:
- **[REQ-2.1]** Финансовая точность (Decision: Decimal types).
- **[REQ-2.2]** Надежная работа в сети (Decision: Locking & Retries).
- **[REQ-2.3]** Высокая производительность (< 2 мин на 100+ файлов) (Decision: Bulk SQL Insert).
- **[REQ-2.4]** Отзывчивый UI (Decision: Background Worker Threads).

## 3. Архитектурный подход (Approach)
**Выбранный подход**: Гибридный кэш (SQL + Excel).
**Обоснование**: SQL-индексы и транзакционность гарантируют целостность данных и молниеносную агрегацию (Traces To: REQ-1.1, REQ-2.3).

**Матрица решений (Decision Matrix):**
| Критерий | Вес | Подход 1 (Excel) | **Подход 2 (SQL Кэш)** | Подход 3 (Worker) |
|-----------|--------|-----------------|-------------------------|-------------------|
| Производительность | 30% | 2 (Low) | 5 (High) | 4 (High) |
| Целостность данных | 25% | 3 (Med) | 5 (High) | 4 (High) |
| Простота реализации | 20% | 4 (High) | 3 (Med) | 2 (Low) |
| Надежность в сети | 25% | 2 (Low) | 4 (High) | 5 (Max) |
| **ИТОГО** | 100% | 2.65 | **4.45** | 3.85 |

**Рассмотренные альтернативы:**
- Approach 1 (Pure Excel): Отклонено — не решает проблемы масштабируемости (REQ-2.3) и блокировок (REQ-2.2).
- Approach 3 (Worker Queue): Отклонено — избыточная сложность для локальной Windows-среды.

## 4. Архитектура (Architecture)
### Слои (Layers):
1. **Ingestion Layer**: FileScanner (REQ-1.2), Parallel ExcelReader (REQ-2.3), ValidationEngine (REQ-1.4).
2. **Persistence Layer**: SQLiteManager (REQ-1.1), SessionTracker (REQ-1.3).
3. **Logic Layer**: ConsolidatorService (SQL-агрегация), FinancialTransformer (Decimal расчеты, REQ-2.1).
4. **Export & UI Layer**: MasterWriter (REQ-1.5), GuiMaster (Threaded UI, REQ-2.4).

## 5. Команда агентов (Agent Team)
- **Architect**: Проектирование слоев и схемы БД (REQ-1.1, REQ-2.2).
- **Data Engineer**: SQL-запросы, типизация "Decimal-First" (REQ-1.1, REQ-2.1).
- **Coder**: Реализация Ingestion Layer, UI-контроллера и интеграция компонентов (REQ-1.2, REQ-2.4).
- **Tester**: Unit/Integration тесты для логики и валидации (REQ-1.4, REQ-1.5).
- **Technical Writer**: Документация (USER_GUIDE.md, BUSINESS_LOGIC.md).
- **Code Reviewer**: Финальный аудит качества и безопасности.

## 6. Оценка рисков (Risk Assessment)
- **[Risk-1.1]** Сбои при синхронизации Excel ↔ SQL. *Мера: Транзакционный импорт.*
- **[Risk-1.2]** Ошибки маппинга колонок (REQ-1.4). *Мера: Промежуточный Staging слой в БД.*
- **[Risk-1.3]** Конфликты блокировок в сети (REQ-2.2). *Мера: Retries с экспоненциальной задержкой.*
- **[Risk-1.4]** Сложность отладки SQL-логики. *Мера: Вынос арифметики в Python Logic Layer.*

## 7. Критерии успеха (Success Criteria)
- **[MET-1.1]** Время консолидации 100+ файлов < 2 минут.
- **[MET-1.2]** Нулевая финансовая погрешность (сравнение версий).
- **[MET-1.3]** Корректная обработка сетевых блокировок (Retries).
- **[MET-1.4]** Четкое разделение слоев кода (Архитектурный аудит).
- **[MET-1.5]** 100% выявление "битых" входящих файлов.
- **[MET-1.6]** Отсутствие зависаний интерфейса (Threaded UI).
