# Unconventional Manual Testing Plan: Design Document

## 1. Problem Statement
Текущая архитектура приложения (v5.5) претерпела фундаментальные изменения: внедрено гибридное кэширование (SQLite WAL), смарт-отслеживание файлов (Inode/MD5) и модульная MVC структура. Базовое тестирование пройдено, однако система должна быть абсолютно устойчива к агрессивным и непредсказуемым действиям в реальной бизнес-среде Windows.
**Цель:** Создать исчерпывающий, нестандартный план ручного тестирования в формате "ролевых миссий". План должен заставить тестировщика мыслить как диверсант или крайне хаотичный пользователь, целенаправленно атакуя файловую систему, MS Excel интеграцию, фоновые потоки и целостность базы данных, чтобы доказать 100% надежность приложения перед релизом.

## 2. Requirements (Functional, Non-Functional, Constraints)
**Функциональные требования:**
- **Формат ролевых миссий:** План должен быть разбит на 3-4 независимые "миссии" от лица разных персонажей.
- **Структура шагов:** Каждая миссия должна содержать конкретные деструктивные шаги (Action) и точный ожидаемый результат (Expected Result).
- **Трекинг прогресса:** План обязан включать чек-листы (`[ ]`) для каждого шага.

**Нефункциональные требования:**
- **Глубина покрытия (Deep):** Тестирование не ограничено таймбоксами. Приоритет — выявление самых маловероятных, но фатальных багов.
- **Правило "Hard Stop":** Любой UI-крэш (вылет), зависание потока или молчаливое искажение данных в Excel мгновенно проваливает тест.

**Ограничения (Constraints):**
- **Vanilla Windows:** Имитация сбоев должна происходить исключительно средствами ОС Windows (Проводник, Диспетчер задач) и MS Excel. Без применения специализированного ПО.

## 3. Approach (Selected Approach, Alternatives Considered, Decision Matrix)
**Выбранный подход: Role-Based Destructive Testing (Ролевое деструктивное тестирование)**
План будет построен вокруг 4-х персон:
1. **"Жонглер файлами"**: Пытается сломать систему ввода-вывода (File Lock, Inode/MD5 changes).
2. **"Хаотичный кликер"**: Атакует GUI и потоки (спам кнопок, закрытие окон).
3. **"Злой бухгалтер"**: Пытается отравить движок парсинга IngestionEngine (битые форматы, скрытые листы).
4. **"Математик-экстремал"**: Ищет дыры в бизнес-логике LogicService (экстремальные комиссии, возвраты).

**Альтернативы (рассмотрено):**
- Академический модульный план: (Отклонено — скучно проходить мануально, упускает баги на стыке модулей).
- Автоматизированные End-to-End тесты: (Отклонено — противоречит задаче "максимально всё мануально протестировать").

**Decision Matrix:**
| Критерий (Вес) | Ролевой подход (Выбрано) | Модульный подход | Автоматизация |
|-----------------|--------------------------|-------------------|---------------|
| Обнаружение корнер-кейсов (40%) | 5 | 3 | 2 |
| Вовлеченность тестировщика (30%)| 5 | 2 | N/A |
| Легкость написания плана (30%) | 3 | 5 | 1 |
| **Итог** | **4.4** | **3.3** | **-** |

## 4. Risk Assessment
- **Фантомные процессы (Зомби-Excel):** Жесткие тесты с принудительной блокировкой файлов могут оставить скрытые фоновые процессы `EXCEL.EXE`. 
  - *Митигация:* В план добавлена инструкция по запуску `taskkill /f /im excel.exe`.
- **Смешивание кэша (Dirty State):** Риск того, что баг из первой миссии перетечет во вторую через SQLite WAL базу. 
  - *Митигация:* Введена строгая инструкция по очистке базы перед каждой миссией.

## 5. Success Criteria
План считается успешно пройденным (Архитектура v5.5 стабильна), если соблюдено правило **Zero Unhandled Crashes & Perfect Data Integrity**:
1. Все 4 миссии полностью пройдены (чек-боксы отмечены).
2. Приложение ни разу не "вылетело" без ошибки в логе.
3. Финальный сгенерированный Master Report математически точен, либо приложение безопасно прерывает генерацию с уведомлением пользователя.
