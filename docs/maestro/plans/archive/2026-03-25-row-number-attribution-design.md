# Design Document: Fix Row Number Attribution

## 1. Problem Statement
Текущий процесс консолидации использует метод `pandas.DataFrame.dropna` для предварительной фильтрации пустых строк до итерации. Из-за этого смещаются индексы строк. При генерации поля "Сотрудник [Файл.xlsx] (стр. N)" номер строки N берется из отфильтрованного массива (через `enumerate(records)`), что приводит к указанию неверного номера исходной строки Excel (например, стр. 5 вместо стр. 10). 
Цель: обеспечить 100% точную атрибуцию номеров строк для всех данных в сводном отчете, сохранив при этом производительность.

## 2. Approach

**Selected Approach: Сохранение Индекса**
Сразу после загрузки листа (через `pd.read_excel`) мы добавим новую колонку, например, `__original_row_idx__`, заполненную диапазоном. После выполнения `dropna` эта колонка сохранит исходные номера строк. В цикле мы будем брать значение из `row_dict.get('__original_row_idx__')`. 
Определение номера строки: `df['__original_row_idx__'] = df.index + header_idx + 2`. — *[Это позволяет сохранить оригинальные номера строк даже после отбрасывания пустых строк через dropna, удовлетворяя требованию высокой производительности.]*

**Alternatives Considered**
*   Перебор Всех: Отказаться от `dropna` и делать все проверки `isna` внутри цикла `to_dict('records')`. Отклонена из-за более высокой нагрузки на цикл (снижение производительности) при работе с огромными массивами пустых ячеек Excel.

**Decision Matrix**
| Criterion | Weight | Сохранение Индекса | Перебор Всех |
|-----------|--------|--------------------|--------------|
| Точность строк | 50% | 5: Гарантирует точное сопоставление | 5: Естественное соответствие индексам |
| Производительность | 50% | 5: Сохраняет преимущества dropna | 3: Накладные расходы на пустые строки |
| **Weighted Total** | | **5** | **4** |

## 3. Risk Assessment
1. Ошибка сдвига на 1 (Off-by-one error): Индекс `pandas` начинается с 0, а данные в Excel начинаются со строки 2 (после заголовка). Нам нужно правильно задать смещение `__original_row_idx__ = df.index + header_idx + 2`.
2. Поломка тестов: Жестко закодированные ожидания "стр. 1" или подобные в тестовых моках (`test_consolidator.py`) могут упасть. Нужно будет обновить тестовые фикстуры.
