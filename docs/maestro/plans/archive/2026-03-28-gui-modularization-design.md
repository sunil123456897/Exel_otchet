# Дизайн-документ: Модульный GUI

## 1. Постановка проблемы
Файл `gui_master.py` является "Божественным объектом", объединяющим UI и логику оркестрации. Это снижает модульность проекта (Sentrux: 0.33) и затрудняет поддержку.

## 2. Требования
- Разделить UI и бизнес-логику интерфейса (Approach 2: Controllers & Components).
- Вынести стили в `theme.py`.
- Использовать внедрение зависимостей (DI) для связи компонентов.
- Сохранить 100% функционала и визуального стиля.

## 3. Архитектура
### Новая структура:
- `APP/src/theme.py`: Глобальные цвета и стили.
- `APP/src/utils/helpers.py`: Вспомогательные функции (open_path).
- `APP/src/components/`:
    - `sidebar.py`: Панель управления (даты, кнопки).
    - `employee_table.py`: Таблица сотрудников.
    - `stats_panel.py`: Прогресс и итоги.
    - `log_panel.py`: Область логов.
- `APP/src/controllers/`:
    - `app_controller.py`: Логика сборки и координации.
    - `config_controller.py`: Управление конфигом.
- `APP/src/gui_master.py`: Тонкая точка входа (Root).

## 4. План перехода (Roadmap)
1. **Этап 1 (Foundation)**: Создание `theme.py` и `helpers.py`.
2. **Этап 2 (Extraction)**: Поэтапный вынос UI-блоков в `components/`.
3. **Этап 3 (Logic)**: Вынос методов оркестрации в `controllers/`.
4. **Этап 4 (Integration)**: Пересборка `gui_master.py` на базе новых частей.

## 5. Критерии успеха
- Повышение модульности в Sentrux до 0.60+.
- Уменьшение размера `gui_master.py` на 70%+.
- Полная работоспособность всех функций.
