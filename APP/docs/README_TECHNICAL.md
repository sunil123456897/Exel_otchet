# Техническая документация: Master-Report v6.0 (Refactored)

## 1. Обзор системы
Master-Report — это высокопроизводительное настольное приложение на языке Python, предназначенное для автоматизированного сбора, очистки и консолидации финансовых отчетов сотрудников. В версии 6.0 внедрена гибридная архитектура (SQL + Excel), обеспечивающая экстремальную надежность и скорость при работе с сотнями файлов в локальной сети.

## 2. Четырехслойная архитектура
Система разделена на четкие слои ответственности для упрощения поддержки и тестирования:

1.  **Ingestion Layer (`ingestion.py`)**:
    *   Сканирование директорий и идентификация файлов.
    *   "Умное отслеживание" изменений (inode + MD5 fingerprint).
    *   Параллельное чтение Excel (.xlsx, .xlsb) в режиме `read_only`.
    *   Первичная нормализация данных и извлечение дат из имен листов.

2.  **Persistence Layer (`sqlite_manager.py`, `db_schema.sql`)**:
    *   Управление SQLite БД как промежуточным вычислительным ядром.
    *   Хранение сессий, метаданных файлов и "сырых" строк (Staging Area).
    *   Обеспечение целостности данных через транзакции и WAL-режим.
    *   Механизмы повторных попыток (Retries) при сетевых блокировках.

3.  **Logic Layer (`logic_service.py`)**:
    *   Бизнес-логика консолидации: группировка, фильтрация, расчет комиссий.
    *   Использование типа `Decimal` для всех финансовых вычислений (нулевая погрешность).
    *   Валидация данных и применение правил переопределения (Overrides).

4.  **Export & UI Layer (`writer.py`, `gui_master.py`)**:
    *   Генерация итогового Excel-отчета с сохранением стилей и форматирования.
    *   Многопоточный GUI на Tkinter, обеспечивающий отзывчивость интерфейса во время тяжелых операций.

## 3. Схема базы данных (SQLite)
Использование БД позволяет мгновенно агрегировать данные и отслеживать историю изменений без повторного чтения всех Excel-файлов.

*   **`sessions`**: Регистрация каждого запуска (ID, время, статус).
*   **`source_files`**: Реестр всех найденных отчетов. Хранит `inode` (для детекции переименований) и `file_hash` (MD5 первых 8КБ для детекции изменений содержимого).
*   **`staging_data`**: Промежуточное хранилище всех строк из всех файлов в формате JSON. Позволяет выполнять сложные SQL-выборки перед финальной обработкой.
*   **`consolidated_results`**: Кэш финальных расчетов для ускорения повторной генерации отчетов.

## 4. Ключевые механизмы надежности

### 4.1. Умное отслеживание (Smart Tracking)
Для минимизации дисковых операций система использует комбинацию:
*   **Inode**: Уникальный идентификатор файла в файловой системе. Позволяет понять, что файл был переименован или перемещен, но остался тем же самым.
*   **MD5 Fingerprint**: Хэш-сумма начального блока данных. Позволяет мгновенно определить, изменилось ли содержимое файла, не читая его целиком.

### 4.2. Сетевая устойчивость (Network Resilience)
При работе с файлами на сетевых дисках (SMB/CIFS) часто возникают блокировки. Master-Report решает это через:
*   **WAL Mode (Write-Ahead Logging)**: Позволяет одновременно читать и писать в БД, минимизируя `database is locked`.
*   **Exponential Backoff Retries**: При обнаружении блокировки (SQLite или Excel) система делает до 5 попыток с увеличивающейся паузой (настраивается в `config.yaml`).

## 5. Стек технологий
*   **Язык**: Python 3.12+
*   **БД**: SQLite 3 (с поддержкой Decimal через адаптеры)
*   **Работа с Excel**: openpyxl, pyxlsb
*   **Конфигурация**: YAML
*   **Интерфейс**: Tkinter + Threading
