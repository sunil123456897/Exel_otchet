## 2. Исправление критических багов

### 2.1. Точность финансовых данных
- **NUMERIC → TEXT миграция:** колонки `amount`, `total_amount`, `commission`, `net_amount` переведены с NUMERIC (float-потеря точности) на TEXT (точный Decimal). Миграция `001_numeric_to_text.sql` с авто-бэкапом БД перед применением.
- **Decimal прямо в Excel:** `export_writer.py` теперь пишет `Decimal` напрямую, без конвертации в `str` и обратно. Раньше большие суммы теряли копейки.
- **Fail-soft парсинг сумм:** `_to_decimal_soft()` в сверке — некорректная ячейка не роняет весь отчёт, а логируется в `data_loss.log` и строка пропускается.

### 2.2. Ложные срабатывания валидатора (3 бага в `logic_service.py`)
- **Word-boundary matching для header words:** `_DEFAULT_HEADER_WORDS` ("итого", "всего", и т.д.) теперь используют regex `\b` — "доп" совпадает с "доп оплата", но НЕ с "недопустимый".
- **Word-boundary для income_overrides:** `"доп"`, `"доп сф"`, `"% посред"` — те же правила границ слов.
- **Проверка цифр в `_is_header_line()`:** строка с реальными цифрами не помечается как заголовок, даже если содержит слово "итого".

### 2.3. Стабильность инфраструктуры
- **EventBus race condition:** исправлена гонка потоков при доставке событий
- **Атомарность миграций:** DDL + запись в `_migrations` выполняются в одной транзакции `BEGIN IMMEDIATE` — сбой между ними не оставляет полуприменённую миграцию
- **Source-file write errors:** `source_file_repo.py` теперь не падает при ошибке записи, а логирует
- **SQLite Decimal adapter:** регистрируется один раз (раньше при каждом подключении)
- **Marshal Tk callbacks:** GUI-колбэки из фоновых потоков теперь безопасно маршалируются в main thread
- **Workbook close guarantee:** `openpyxl.Workbook` гарантированно закрывается даже при ошибке

### 2.4. Специфические баги данных
- **Sanitize «Источник»:** поле Источник очищается от спецсимволов перед записью
- **Fail-soft для курс/сумма:** `safe_decimal()` обрабатывает курс валют и сумму — краш автосверки Ивана устранён
- **Validator не сканирует метаданные:** служебные строки не проверяются на header words — кураторские батчи больше не обнуляются
- **«список р/с» в allowed headers:** добавлен в список разрешённых вспомогательных заголовков — источники больше не подсвечиваются красным

### 2.5. Запись потерь данных
- **`data_loss_log`:** `staging_repo.py` записывает потерю при молчаливом нуле `amount` — раньше данные просто исчезали без следа
- **`_process_batch_with_retry`:** пакетная обработка с retry при ошибке записи

## 3. Система алиасов заказчиков (новая функция)

### Назначение
Бухгалтеры вручную указывают соответствия между заказчиками кураторов и заказчиками РСЧ. Сверка автоматически сопоставляет строки с разными названиями.

### Логика сверки
- **«Сверено»** = точное совпадение суммы + исполнителя + заказчика (или алиаса) — 3 критерия
- **«Проверить»** = частичное совпадение → бухгалтер смотрит и добавляет алиас
- В следующий раз та же строка автоматически «Сверено»

### Реализация
| Компонент | Файл |
|---|---|
| Миграция БД | `APP/migrations/002_customer_aliases.sql` |
| Репозиторий | `APP/core/infra/customer_alias_repo.py` — CRUD + кэш + case-insensitive matching |
| Логика сверки | `APP/core/infra/reconciliation/_collect.py` — `_customer_exact_or_alias_match()` |
| Контроллер | `APP/core/app_controller.py` — `get/add/update/delete_customer_aliases` |
| UI вкладка | `APP/core/ui/ui_aliases.py` — таблица + диалоги добавления/редактирования |

### Особенности
- Сравнение **двунаправленное** — не важно, в какой колонке что
- Регистр и пробелы **не важны** — система нормализует автоматически
- **Ё = Е** автоматически
- Алиас проверяется по полям «Заказчик» и «Контрагент» РСЧ

## 4. Адаптивный интерфейс (DPI-awareness)

### 4.1. DPI-awareness
- `SetProcessDpiAwareness(2)` в `main.py` перед `tk.Tk()` — чёткий текст на HiDPI мониторах (125%/150%/200%)

### 4.2. Масштабирование темы
- `ThemeManager.init_scaling(root)` — вычисляет коэффициент от DPI монитора
- Все шрифты (`FONTS`), отступы (`SPACING`), `rowheight`, `padding`, `scrollbar width`, `progressbar thickness` масштабируются через `_scale`
- Базовые значения хранятся в `_BASE_FONTS` / `_BASE_SPACING`, пересчитываются при инициализации

### 4.3. Адаптивность виджетов
| Проблема | Фикс |
|---|---|
| Фиксированные ширины колонок Treeview (5 таблиц) | `stretch=True` для широких колонок |
| Текст обрезается на узких окнах | `wraplength=600` для `state_label` |
| Entry не растягивается в настройках | `grid_columnconfigure(1, weight=1)` + `sticky="ew"` |
| Фиксированные `height=` у Text/Listbox | Убраны — родитель `expand=True` |
| Сайдбар 300px фиксировано | `max(260, min(360, screen_w*0.22))` |
| Прогрессбар `length=120` конфликтует с `fill=tk.X` | Убран `length` |
| Хардкод шрифтов в `LogPanel` | `ThemeManager.FONTS` вместо `('Segoe UI', 9)` |
| Логи `wrap=tk.NONE` — нет переноса | `wrap=tk.WORD` |
| `minsize(900, 600)` — много для нетбуков | `max(640, screen_w*0.5)` |

### 4.4. Тёмная тема
- **Баг:** `tag_configure('odd'/'even'/'hover'/'ready'/'missing')` вызывались один раз со светлыми цветами → при переключении на тёмную тему сотрудники становились невидимыми (светлый текст на светлом фоне)
- **Фикс:** `EmployeeTable.refresh_theme()` и `DashboardTabs.refresh_theme()` переапплицируют теги при переключении темы

## 5. Производительность

### 5.1. Ускорение ингестии
- **Pre-compile trash-row regex:** регулярные выражения для фильтрации мусорных строк компилируются один раз → **ускорение ~3.5x** при чтении файлов
- Раньше: `re.match()` вызывался для каждой строки с компиляцией pattern каждый раз

### 5.2. Бенчмарк (локальный SSD, 22 файла, 507 строк)

| Операция | Время |
|---|---|
| Discovery (23 сотрудника) | 0.03s |
| Ingestion (22 файла) | 0.14s |
| Logic (apply_financial_rules) | 0.02s |
| Excel Export | 2.13s |
| RSCH (6 файлов) | 2.55s |
| Reconciliation | 1.56s |
| **Итого** | **6.4s** |

### 5.3. Устойчивость к сетевым задержкам
- Симуляция: 0ms (SSD) / 50ms (хорошая сеть) / 200ms (плохая сеть)
- **Результат:** задержка не влияет — calamine (C-extension) читает xlsx на C-уровне, минуя Python `open()`
- 90% времени занимает openpyxl форматирование (CPU-bound, не I/O)

### 5.4. Отключение calamine-изоляции
- `isolate_calamine: false` — раньше каждый файл читался в отдельном subprocess, который зависал на переполненном pipe-буфере (deadlock `Popen` + `PIPE`)
- Теперь: файлы читаются in-process за 0.02s вместо 5+ минут зависания

## 6. Система обновлений и развёртывания

### 6.1. Чистая установка с нуля
- Клиент скачивает zip с GitHub → запускает `ЗАПУСК.bat`
- Автоматически: создание `.venv`, `pip install`, генерация `config.yaml` из `config.example.yaml`, создание `cache.db`, применение миграций
- Проверено в чистой среде: venv + deps + config + DB + миграции — всё создаётся без ошибок

### 6.2. Обновление с сохранением данных
- `ОБНОВИТЬ_И_ЗАПУСТИТЬ.bat` → `tools/update_from_github.ps1`
- **Бэкапит** локальные файлы перед обновлением:
  - `APP/config.yaml` — настройки пользователя
  - `APP/employees.yaml` — пути к файлам сотрудников (Q:\, Z:\, \\server\share\)
  - `APP/cache.db` — база данных
- **Копирует только код** (`APP/core`, `APP/main.py`, `APP/migrations`, `requirements.txt`, батники)
- **Восстанавливает** локальные файлы после копирования
- Проверено: MD5 файлов до и после обновления **совпадают**

### 6.3. Исправления скрипта обновления
- **Баг:** `APP/migrations/` не копировался при обновлении — миграции (включая `customer_aliases`) не доходили до клиентов. Добавлен в `$UpdateItems`.
- **Защита:** allowlist + проверка пересечений с локальными данными — обновление не может затереть данные пользователя

### 6.4. Безопасность обновлений
- `PinnedCommitSha` — закрепление конкретного commit SHA для проверки целостности
- Три стратегии обновления с откатом:
  1. `git fetch` + `git archive` (если есть `.git`)
  2. `git init` + shallow fetch (если нет `.git`)
  3. ZIP-скачивание (если нет git)

- БД не растёт бесконечно

### 7.4. Graceful skip для свежей БД
- `"no such table"` ошибки при миграции → graceful skip + mark as applied (свежая БД уже имеет TEXT-колонки из `db_schema.sql`)
